# dsh-bots 架构设计（基于核实 API 的修正版）

承接 `dsh-my-bot设计稿.md` 的产品目标与取舍（§19 不变），本文给出经过 Phase 0 API 核实后的落地架构。与设计稿的差异均已标注 ⚠️ 并给出依据（见 01-DSH-API-调研报告.md）。

## 1. 总体架构

```
┌────────────────────────── DSH Host 进程 ──────────────────────────┐
│                                                                    │
│  dsh-bots 插件（out-of-tree bundle，host 半体 + web client 半体）    │
│  ┌──────────────────────────────────────────────────────────────┐ │
│  │ BotWorkbench UI (dsh.client, React)                          │ │
│  │   Home / Bots / Bot Detail / Chat / Groups / Tasks / Presets  │ │
│  └───────────────┬──────────────────────────────────────────────┘ │
│                  │ ctx.remote.* / webServer REST /api/plugins/bots │
│  ┌───────────────┴──────────────────────────────────────────────┐ │
│  │ Host 侧模块                                                   │ │
│  │  BotManager   TeamManager   GroupManager   TaskManager        │ │
│  │  SessionManager(统一入口)   MessageManager(Inbox+Delivery)     │ │
│  │  PresetAdapter   PermissionManager   SkillCatalog   Memory    │ │
│  │  Storage(storageDomain + stateDir JSONL)   Routines(M4)       │ │
│  └──────┬──────────────┬───────────────┬────────────────────────┘ │
│         │              │               │                          │
│   ctx.agentPresets  ctx.agents    ctx.schedule / subagents /      │
│   (list/resolve/    (create/resume/ approval / systemPrompt /      │
│    readDocument)    followup)     webServer / sessionQuery         │
│         │              │                                          │
│   DSH Agent Preset Registry     DSH Agent Runtime & Session Log    │
└────────────────────────────────────────────────────────────────────┘
```

核心不变式（全部有宿主原生支撑）：

- **Bot = Identity(插件自有) + presetId(引用) + Session 集合(原生)**。
- Session 创建时经 `CreateAgentOptions.meta.agentPreset` 绑定 preset；恢复无 preset 字段 → 历史会话组合天然锁定（宿主 `agent-preset/locked` 兜底）。
- 插件不存对话历史，只存 `dshSessionId` 绑定（`sessionPersistence` 是唯一历史来源）。

## 3. 关键流程（修正版）

### 3.1 Bot 创建（Reference / Fork 双模式）

Reference：`PresetAdapter.list()`（`agentPresets.list()`）→ 选 preset → 保存 BotDefinition（仅 `presetId`）。

Fork ⚠️ 修正：`readDocument(sourceId)` 取组合 YAML → 用户在 UI 编辑（增删插件行/skills）→ `PresetForker` 生成 bundle 目录（patch insert `@deepseek-ai/dsh-agent-preset` 行，`config.id = <bot-scoped-id>`）→ `plugin_manager install_bundle` → 安装成功后 BotDefinition 绑定新 presetId；失败则回退 Reference 并提示。**不复制目录、不手写平行 Registry。**

### 3.2 会话创建（SessionManager 唯一入口）

```
resolveBot(botId) → 校验 presetId 可 resolve（否则标记 unavailable，禁建新会话）
  → agents.get(knownSessionId)  借用活 agent
  → 否则 agents.create({ sessionId, meta:{ cwd, agentPreset }, agentOptions:{provider,model} , setup})
  → 落库 BotSessionBinding{ dshSessionId, presetId, type, status }
  → agent.followup(userMessage(text)); await agent.whenIdle()
```

三类会话（direct/group/task）都是原生 Session，仅 `type` 与关联（groupId/taskId）不同。群聊 = 统一 Transcript（插件 JSONL）+ 每 Bot 独立 Session（设计稿方案 B，核实结论支持：一个 Session 一个组合，无法多 preset 共享）。群聊上下文注入走 `setup()`/`system-prompt/assemble` 钩子，作为标注的外部协作上下文 section 注入最近 N 条 + 摘要，不写入 Bot 私有记忆。

### 3.3 消息与任务（持久优先）

- Inbox 落盘（append-only）→ 授权检查 → Delivery（幂等键 = messageId+recipient）→ SessionResolver → SessionHandle 执行 → 结果消息回写 → 通知。
- 恢复策略照搬 grokbot 验证过的范式：重启后 in-flight 任务标 `interrupted` 不自动重放；消息以持久队列为准；重试保留 `retryOf` 历史。
- Task 约束（§7.5 默认值）在 Dispatcher 中强制：深度≤2、并行≤3、超时 10min、循环委派检测（任务链回溯）。

### 3.4 Bot 间通信

不复制 grokbot 的"每消息开 subagent"：长期 Bot 间通信 = Direct Message 进对方 Inbox → 对方 Bot 的 direct/task session 执行；一次性并行子任务才用 `ctx.subagents`（`startActivation`，可指定 preset）。给 Bot 注册的团队工具（`team_send_task` / `team_message` / `team_list_members` …）在 `setup(agentCtx)` 挂载，工具内部走 MessageManager（持久、可审计），不走进程内 EventEmitter。

## 4. REST API（`webServer.register`，前缀 `/api/plugins/bots`）

路径与设计稿 §12 一致（bots/groups/tasks/presets CRUD + chat/messages/cancel/retry/validate/copy）。实现注意：
- 全部路由 handler 做参数校验（zod）+ 组织权限检查 + 错误映射（含 `agent-preset/not-found|locked` → 4xx 语义）。
- 消息发送复用 Inbox 幂等键，HTTP 重试安全。
- 流式状态用现有 Remote stream（`session/follow`、`observeState`），不自建 WS。

## 5. UI（dsh.client 半体）

- `dsh.client: { inject: [...client-runtime/ui-slots], platform: 'web' }`（grokbot 验证）。
- 页面按设计稿 §11.2：Home/Bots/BotDetail/DirectChat/Groups/Tasks/Presets/Settings。
- Bot 运行状态不前端自造：由 Host 侧从 `sessionQuery`/agents 活跃度 + 任务状态推导（`BotRuntimeStatus`），经 Remote stream 推送。
- Bot Detail 的"Preset 状态"来自 roster 的 `broken` 字段与 `resolve()` 探测；旧会话标注用 `sessionProjections.snapshot(session).agentPreset`。

## 6. 工具与权限

- 组织权限（owner/admin/member/observer，§3.3 表）在 PermissionManager 强制于 API 与团队工具两层。
- Bot 工具面由其 Preset 决定；插件团队工具默认只含消息/任务类（低危），文件/Shell 能力完全来自 preset 组合 + 宿主沙箱与审批（`approval` 服务、`DSH_PERMISSION_MODE`），插件不扩大权限。
- Bot 工作区隔离：每 Bot `meta.cwd` 指向 `~/.dsh/bots/workspaces/<botId>/`（或用户指定）；跨 Bot 工作区访问在工具层拒绝。

## 7. 与设计稿的其余差异汇总

| 项 | 设计稿 | 本设计 | 依据 |
|---|---|---|---|
| Preset 存储 | `~/.dsh/.agent-presets/` 目录 | profile patch 插件行 | Registry 不扫目录（README 原文） |
| Fork | 复制 Preset 目录 | 生成 bundle + `install_bundle` | 同上；README 指定的正式途径 |
| 持久化 | SQLite | `storageDomain`(zod 域) + stateDir JSONL | 无原生 SQLite 依赖；宿主设施已备 |
| Bot 执行 API | "调用 DSH 原生接口（待查）" | `agents.create/resume + followup/whenIdle`，`meta.agentPreset` | 源码核实 + grokbot 实证 |
| 群聊会话 | 方案 B（推荐） | 维持方案 B | 一个 Session 一个组合（核实） |
| 工具启用 | 未明确 | patch 不默认 re-enable bash/fs；工具面交给各 Bot preset | 最小权限 |

## 8. 里程碑裁剪（映射设计稿 §17）

- **M1**：Preset Adapter（list/resolve/readDocument）+ PresetForker + BotManager + SessionManager/SessionHandle + direct chat + 最小 UI（Bots 列表 + 聊天）。验收标准照设计稿 M1 七条（Fork 条目按 bundle 途径验证）。
- **M2**：Team/Group/Inbox/Delivery/@mention 路由 + 状态展示 + 重启恢复。
- **M3**：TaskManager/Dispatcher/Retry/Cancel + Chief 汇总（端到端剧本 = 设计稿 M3 八步）。
- **M4**：Memory 分层、Routine（接 `ctx.schedule` delivery→任务会话）、Webhook（`webhookRuntime`）、外部 Inbox。
