# dsh-bots 数据模型与存储设计

## 1. 存储总览

```
~/.dsh/bots/                      # stateDir = dshHomePath('bots')
├── domain/                       # storageDomain 持久化（结构化数据，zod 校验）
├── transcripts/
│   ├── dm/<botId>.jsonl          # 私聊转录（append-only）
│   └── groups/<groupId>.jsonl    # 群聊统一 Transcript
├── tasks/<taskId>/
│   ├── task.json                 # 快照（含 runs/artifacts 索引）
│   └── result.md                 # 结果正文
├── bots/<botId>/memory/          # Private Memory（Markdown，按主题文件）
├── teams/<teamId>/memory/        # Group Memory
├── workspaces/<botId>/           # Bot 会话默认 cwd
└── inbox/queue.jsonl             # 待投递队列（append-only + 消费水位）
```

原则：对话正文历史只存 DSH 原生 session log（插件只存 `dshSessionId`）；插件转录 JSONL 是**协作层展示副本**（群聊统一视图 / 审计），不是还原会话的来源。

## 2. storageDomain 声明（domain name: `dsh-bots`, version: 1）

表与设计稿 §13.1 对应，字段类型以 zod 表达（摘要）：

```ts
// core/types.ts —— 领域类型（同时投影为 API/Remote wire schema）
BotsTable: Record<BotId, BotDefinition>   // 键 = botId
TeamsTable: Record<TeamId, BotTeam>
TeamMembersTable: Record<`${teamId}:${botId}`, { role: 'owner'|'admin'|'member'|'observer' }>
SessionsTable: Record<SessionBindingId, BotSessionBinding>   // 含 dshSessionId 唯一索引
GroupsTable: Record<GroupId, BotGroup>
MessagesTable: Record<MessageId, BotMessage>
DeliveriesTable: Record<`${messageId}:${recipientBotId}`, MessageDelivery>  // 幂等键即主键
TasksTable: Record<TaskId, BotTask>
TaskEventsTable: Record<`${taskId}:${seq}`, TaskEvent>
MemoryRefsTable: Record<RefId, { owner: BotId|TeamId|TaskId; kind; path }>
RoutinesTable: Record<RoutineId, BotRoutine>   // M4
Global: { schemaVersion, defaultTeamId, taskPolicy: TaskPolicy, recoveredAt? }
```

实体字段沿用设计稿 §2.2/§3.1/§4.2/§5.2/§7.1/§10 定义，补充：

- `BotDefinition`：不变（`presetId` 核心字段；`modelOverride` 落到 `agentOptions`）。
- `BotSessionBinding`：`dshSessionId` 建立唯一映射；`presetId` 为**创建时快照**（展示用，真实值以 session 投影 `agentPreset` 为准，两者不一致时以投影为准并提示）。
- `MessageDelivery`：主键即幂等键，attempts/lastError/updatedAt 支撑重试。
- `BotTask`：`status` 增加 `interrupted`（重启恢复标记，见 §4）。

迁移：`DomainSpec.version` + `compatibleVersions`；表 schema 变更必须让旧记录可被新 schema 接受（新增字段 optional），否则 bump version 并写迁移例程。派生性数据（Deliveries 可重建部分）可对个别表用 `invalidRecords: 'backup-and-skip'`。

## 3. 完整性规则（对应设计稿 §13.2）

- 删除 Bot：软删除（`enabled=false` + `deletedAt`），解除团队/群组关系；**不动**原生 session 与工作区文件（工作区清理需用户显式确认）。
- 删除群组：Transcript 归档到 `archive/`，不删成员 session。
- 删除/归档任务：只归档；`task_events` 全保留。
- Preset 引用检查：删除 fork 出的 preset bundle 前，扫描 `bots` 表与 `sessions` 表引用；仍有引用时阻止（设计稿 §1.1 规则）。
- 消息分页：`listMessages(scope, cursor=watermark)`，watermark = JSONL 行号。
- 备份：`domain/` 目录 + `*.jsonl` 为纯文件，定期 tar 快照到 `~/.dsh/bots/backups/`（保留最近 N 份）。

## 4. 恢复语义（启动序列，对应设计稿 §15.1）

```
plugin start
 → storageDomain.open(spec)            # 版本校验/迁移
 → 校验 preset 引用（agentPresets.resolve，失败→标记 unavailable，不删 Bot）
 → 重放 inbox 水位之后的 pending 消息（幂等键去重）
 → tasks: status ∈ {running, waiting} → interrupted；不自动重放，等用户/Chief retry
 → sessions: 对 interrupted 任务关联的 binding 做 stat 校验（sessionPersistence.stat），
     不存在→ binding.status='error'（不伪造）
 → 订阅事件（agent-preset/selected, session/event, approval/request…）
 → webServer 路由 + Remote 导出 → ready
```

卸载：停收新任务 → 取消插件 `ctx.effect` 注册的后台调度 → 关闭 domain → 保留全部 stateDir 文件。
